# AIニュースまとめ 設計書（仕様書）

作成日: 2026-10-17

## 1. 目的

日本語のAI関連ニュースを毎日自動で集め、サンプルページ（`ai-matome-sample.html`）と同じ見た目の
Webページとして GitHub Pages で無料公開する。作る人はプログラムの知識がないため、
すべて初心者が手で直せる形にする。

## 2. 守るルール（依頼者の指定）

1. お金がかかるもの（有料の要約サービスなど）は使わない。無料の範囲だけで動かす。
2. 日本語の情報だけを載せる。
3. 記事ごとに載せるのは次の5つだけ。**本文は載せない。必ず元記事へのリンクを付ける。**
   タイトル / 公開日 / サイト名 / 冒頭の短い説明（100文字以内）/ 元記事のURL
4. サンプルの「どんな話？／どう役に立つ？」は「記事の冒頭」に置き換える。
   「これは試作です」の注意書きと仮のリンクは外す。

## 3. 使うニュースサイト（依頼者が承認した4つ）

| サイト名 | RSSのURL | AI専門か（ai_only） | 備考 |
|---|---|---|---|
| ITmedia AI＋ | https://rss.itmedia.co.jp/rss/2.0/aiplus.xml | はい | 下記の注意あり |
| GIGAZINE | https://gigazine.net/news/rss_2.0/ | いいえ | |
| ASCII.jp | https://ascii.jp/rss.xml | いいえ | 引用するときはサイト名の明記が必要 |
| Publickey | https://www.publickey1.jp/atom.xml | いいえ | Atom形式（RSSの仲間） |

除外したサイト: ギズモード・ジャパン（利用規約で無断転載を禁止）、Zenn（個人の投稿記事でニュースサイトではない）。

### 利用条件についての注意（依頼者が承知済み）

- ITmedia AI＋の「RSSのご利用条件」には、「記事の一部だけを抜き出すこと・改変」の禁止、
  「発信元の表示」の義務、「アプリ等への組み込みは事前に問い合わせ」が書かれている。
- 依頼者は、**問い合わせをしないで使う**と決めた。ITmedia から条件違反を指摘されたときは、
  `data/sources.json` から外す（依頼者の責任で対応）。
- 発信元（サイト名）は必ず表示し、全記事に元記事へのリンクを付ける。
- 4サイトとも、RSSをこのページに載せてよいと明記した文章は確認できなかった。
  設計者は法律の専門家ではなく、適法性は保証しない。

## 4. 全体の流れ

1. 毎朝6時（日本時間）に GitHub Actions が動く。
2. `scripts/build.py` が4サイトのRSSを読む。
3. AIに関係する記事だけを選び、分野と料金の色を決める。
4. `data/articles.json` に14日分をためる。
5. `template.html` に記事を埋め込み、完成ページ `index.html` を作る。
6. GitHub Pages で公開する。

## 5. ファイル構成

| ファイル | 役目 | 手で直すか |
|---|---|---|
| `scripts/build.py` | RSS読み取り・記事選び・ページ作成（Python標準機能のみ。追加の部品は入れない） | しない |
| `template.html` | サンプルと同じ見た目のひな形 | しない |
| `data/services.json` | サービス名・分野・料金の色・一言説明 | **する** |
| `data/sources.json` | 記事の元になるサイト（名前・RSSのURL・ai_only） | **する** |
| `data/articles.json` | 集めた記事の14日分の保管場所 | しない（自動） |
| `index.html` | 完成したページ（記事を埋め込み済み。ダブルクリックで開ける） | しない（自動） |
| `.github/workflows/update.yml` | 毎朝6時の自動実行の指示書 | しない |
| `README.md` | 初心者向けの使い方 | — |

## 6. データの形

### data/services.json

サービスごとに次の項目を書く。

- `name`: サービス名（記事の検索に使う）
- `aliases`: 別の呼び名（省略可。例: `["OpenAI"]`）
- `category`: `chat` / `image` / `video` のどれか
- `price`: `free`（無料）/ `mid`（無料プランあり）/ `paid`（有料のみ）
- `icon`: 絵文字
- `desc`: 一言説明

最初の一覧は、サンプルページの12サービス（ChatGPT, Claude, Gemini, Microsoft Copilot,
Midjourney, Adobe Firefly, Canva のAI機能, Bing Image Creator, Sora, Runway, Kling, Vrew）。
**料金の色はサンプルの仮の値。依頼者が公式サイトで確認して直す必要がある**（READMEに手順を書く）。

### data/sources.json

サイトごとに `name` / `url` / `ai_only`（true ならAI専門サイト）を書く。

### data/articles.json（1件の形）

`title` / `published`（日時）/ `site` / `summary`（100文字以内）/ `url` / `category` / `service`（なければ空）

## 7. 記事を選ぶルール

1. 各サイトのRSSから、タイトル・公開日・説明文・URLを取り出す。公開日が読めない記事は捨てる。
2. 説明文は、HTMLの記号や画像を取り除いた文字だけにし、先頭100文字で切る（切ったときは「…」を付ける）。
3. **AI関連かの判定**: `ai_only` が true のサイトの記事はすべて対象。
   それ以外のサイトは、タイトルか説明文に「AI」「人工知能」「生成AI」「ChatGPT」など、
   AIを示す言葉（`build.py` の中の一覧）か、`services.json` のサービス名が入った記事だけを対象にする。
4. **サービス名の判定**: タイトルを先に、次に説明文を調べる。複数出てきたときは、
   タイトルの中で最初に出てくるサービスを採用する。英字の名前は、大文字小文字を区別しない。
   短い名前は別の単語の一部（例: ある単語の途中）で誤って当たらないよう、前後が英数字でないときだけ当たりとする。
5. **分野の判定**（上から順に最初に当てはまったもの）:
   1. サービス名が当たったら、そのサービスの分野。
   2. 分野の言葉（画像: 「画像生成」「イラスト生成」など／動画: 「動画生成」「ビデオ生成」など／
      チャット・コード: 「チャットAI」「コード生成」など。一覧は `build.py` の中）が入っていれば、その分野。
   3. どちらでもなければ **「未分類」**。
6. **料金の色**: サービス名が当たったらそのサービスの色。当たらなければ色なし（灰色）。
7. 同じURLの記事は1件にまとめる。
8. 公開から14日たった記事は `articles.json` から消す。
9. 1つの分野（未分類を含む）に表示するのは、新しい順に最大8件。

## 8. ページの見た目と動き

サンプルと同じ見た目（色・フォント・料金ボタン・カード・用語の説明・暗い画面への切り替え）。変更点は次のとおり。

- **タブは4つ**: チャット・コード / 画像づくり / 動画づくり / 未分類（絵文字は 📂）。
  スマホの幅でも4つが並ぶよう、文字を少し小さくする。
- 「サービスのしょうかい」は3つの分野のタブにだけ表示する。**未分類のタブには出さない。**
- 記事カード:
  - 見出しにタイトル、その下にサイト名・公開からの時間・料金バッジ・NEW。
  - 「どんな話？／どう役に立つ？」は外し、**「記事の冒頭」**（100文字以内）を表示する。
  - 開いたところに「元記事を開く（サイト名）」ボタン。**本物のURLにリンクし、新しいタブで開く。**
  - 「これは試作です」の注意書きと「※試作のため…」の注記は外す。
- **「NEW」と「◯時間前」は、ページを開いた時刻から計算する**（公開から24時間以内がNEW）。
  公開から14日を超えた記事は、ページ側でも表示しない。
- 料金ボタン（ぜんぶ／無料／無料プランあり／有料のみ）での絞り込みは、サンプルと同じ。
  色なしの記事は「ぜんぶ」のときだけ表示する。
- ページの下に、記事の著作権は各サイトにあること、料金は変わるので公式サイトで確認することを書く。
- 用語の説明（プロンプト・生成AI・無料枠）はサンプルのまま残す。

### 8-2. 「保存」機能（気になった記事を14日たっても残す）

- 各記事カードに「☆ 保存」ボタンを付ける。押すと「★ 保存ずみ」になり、もう一度押すと保存を外せる。
- 保存した記事は、**それぞれの分野のタブの中**（「新着ニュース」の上）に「保存した記事」として表示する。
  分野は、記事が保存されたときの分野のまま（未分類の記事は未分類のタブ）。
- 保存した記事は、**14日ルールと1分野8件の上限の対象外**。自分で保存を外すまで残る。
- 保存した記事にも、料金の色・サイト名・冒頭・元記事へのリンクを付ける。「NEW」は付けない。
  公開日は「2026年10月17日」のような日付で表示する。
- 保存する中身は、記事の5つの項目（タイトル・公開日・サイト名・冒頭100文字以内・URL）と、分野・料金の色だけ。本文は保存しない。
- **保存先は、閲覧している人のブラウザの中**（ブラウザの保存領域 localStorage。無料）。
  GitHubには保存されないので、公開ページに14日を超えた記事が載ることはなく、他の人には見えない。
- **できないこと（READMEと画面にも書く）**:
  - 別のパソコンやスマホとは共有されない（端末ごとに別）。
  - ブラウザの閲覧データを消す、シークレットモードで使う、などで保存が消えることがある。
  - シークレットモードなどで保存できないときは、「この画面では保存できません」と表示する。
- **バックアップ機能（保存が消えたときの備え）**:
  - ページの下に「保存した記事のバックアップを書き出す」ボタンを置く。押すと、保存した記事の一覧が
    ファイル（`ai-matome-backup-年月日.json`）としてパソコンやスマホにダウンロードされる。
  - 「バックアップを読み込む」ボタンで、そのファイルを選ぶと、保存した記事が元に戻る。
    読み込むときは、いま保存している記事を消さず、同じURLの記事は1件にまとめて足す。
  - 読み込むファイルの中身は、決まった形か確認する。形が違うときは、何も変えずに「このファイルは読み込めません」と表示する。
  - 保存した記事が1件以上あるのに、最後のバックアップから7日以上たったときは、ページ上に
    「バックアップを取りましょう」と目立たない案内を出す。
  - バックアップファイルは、あなた自身で大事な場所（クラウドの保存先など）に置く。
    ページや GitHub には、自動では送られない。
- 保存の読み書きに失敗しても、ページの表示はふつうに動くようにする。
- 保存した記事が増えたときのため、保存した記事の数を各分野のタブの見出しに表示する。
- 記事の文字は、必ずHTMLとして安全な形に変換して表示する（記事側の文字が画面を壊さないように）。

## 9. 自動実行と公開

- `update.yml` は、毎日 21:00 UTC（日本時間の朝6時）に動く。依頼者が手で動かすボタンも付ける。
  GitHub の混雑で、数分〜数十分遅れることがある。
- 動きの中身: 部品の準備（Python）→ `build.py` 実行 → `articles.json` と `index.html` の変更を
  リポジトリに保存（commit）→ GitHub Pages に公開。
- 通信は1日1回。サイトの負担を増やさないため、User-Agent（名乗り）に、このまとめページの名前を入れる。

## 10. 止まったときに気づく方法

- GitHub は、自動実行が失敗すると、依頼者のメールに知らせを送る（初期設定。READMEで確認方法を案内）。
- 4サイトの**すべて**のRSSが読めなかった日は、わざと失敗にして知らせが届くようにする。
- 一部のサイトだけ読めなかった日は、ほかのサイトの記事で続け、動きの記録（ログ）に残す。
- 注意: GitHub は、一定期間（60日）リポジトリに動きがないと、自動実行を止めることがある。
  毎日の記事の保存でリポジトリに動きがあるため、通常は止まらない想定だが、
  READMEに「止まったらActionsの画面で再開する」手順を書く。

## 11. 確認の手順（依頼者のパソコン）

1. Python が入っているか確認する（なければ入れ方を案内）。
2. `python scripts/build.py` を1回動かし、`index.html` ができることを確認する。
3. `index.html` をダブルクリックで開き、4つのタブ・料金ボタン・カード・暗い画面・
   元記事のリンクが正しいことを一緒に確認する。
4. 問題がなければ、GitHub の登録からの公開手順に進む（画面の押す場所を1つずつ案内する）。

## 12. README.md に書く内容

- このページの仕組みの説明（初心者向け）。
- サービスを足す方法（`data/services.json`）。料金の色の意味と、公式サイトで確認する方法。
- 記事の元になるサイトを足す方法（`data/sources.json`）。足す前にRSSの利用条件を確認すること。
- 自動更新が止まったときの気づき方と、再開の方法。
- よくあるつまずき。

## 13. 今回やらないこと

- 有料サービス・有料の要約機能の利用。
- 記事の本文の掲載・保存、画像の掲載。
- ギズモード・ジャパンと Zenn の利用。
- 独自のドメイン名の設定。
- 保存した記事を複数の端末で共有する機能（サーバーが必要で、無料の範囲では難しいため）。
- 保存した記事をGitHubに保存する機能（記事が公開ページに長く載るため。依頼者は「バックアップファイル」方式を選んだ）。
